# RKE 最小维护范围与价值验证

2026-09-11。结论：保留研报解析、带来源和时间的结构化抽取、研究检索及其必要边界；
在证明增益前暂停扩展评分、recipe、工具提案和治理报表链。
这是后续维护决策与实验协议，不代表已经删除这些子系统或完成收益实验。

## 已知事实与证据缺口

RKE 已有真实消费者，不能按“没有交易权限”推断为死代码：

| 调用位置 | 当前职责 | 收缩约束 |
|---|---|---|
| `mosaic-ts/src/agents/tool_contract.ts` 及各层 Agent | 将 `get_rke_research_context` 纳入工具合同 | 不直接删除必需工具或伪造空结果 |
| `mosaic/dataflows/sector_relationship_queries.py`、`sector_relationship_source_evidence.py` | 将检索内容与来源档案、PIT 证据绑定 | 保留来源和可得时间验证 |
| `mosaic/dataflows/frozen_adaptive_queries.py`、`bound_runtime_query_plans.py` | 限定冻结运行可读取的研究上下文 | 不绕开授权范围与快照绑定 |
| `mosaic/rke/agent_research_context.py` | 过滤、排序并生成 public-safe 研究上下文 | 保留隐私白名单、as-of 筛选、research-only 标志 |
| `mosaic-ts/src/agents/rke_footprints.ts` | 从最终输出生成 Agent 诊断行 | 最终输出不能证明读取、引用或验证过哪些研报 |

当前上下文依赖 claims、metadata、outcomes、source/viewpoint profiles、recipes、
tool gaps、weighted contexts、stock/industry snapshots 共十类输入，见
`RKE_AGENT_RESEARCH_INPUT_FILENAMES`。因此“小核心”是目标边界；不能在没有消费迁移的
情况下直接删除 profiles 或 recipes 文件及其生成器。

现有 fixed benchmark 比较 model config × episode/date，没有“不用研报 / 原文检索 /
结构化 RKE”的分组入口。完成率、工具调用数、解析覆盖率、schema/readiness 通过，
都不能单独证明 RKE 改善判断。真实模型运行也不能证明使用过某一份上下文。

## 立即落实的简化

移除图运行结束后的 `rkeAgentResearchContext(max_items=1)` 重查，以及由
`!fakeLlm` 推导 `current_data_confirmed=true` 的开关。事后查询可能取到不同内容，
也无法证明原运行读取或使用了它；把新查询的 hash、rank、claim refs 记为运行证据
会污染 benchmark/replay 归因和下游 RKE 使用评分。每个已完成 Agent 少一次事后查询。

捕获仍保留 Agent、日期、输出类型、置信度桶和 run/episode/model 标识；
`rke_prior_usage_quality=not_evaluated`，理由为 `rke_runtime_usage_unverified`，
不生成上下文 hash、排名或 claim/tool 引用。布尔确认字段保持 false，表示未确认，
不表示已经证明“没有使用”。缺少测量证据也不归因为研报无用或工具失败。

这一变化会使依赖已确认 RKE 使用的 readiness 条件不能由这些诊断行满足，这是正确的
证据边界。后续有效归因必须来自实际运行期间的绑定记录；工具返回、输出引用、
当前数据核验、结果改善是四个不同层次的证据，不能相互替代。

历史行不会自动修正。旧 `used_ranked_prior`、hash 和确认计数不能作为本协议的收益
证据；重新评估须使用新的 benchmark/replay 标识，禁止混入旧汇总。私有历史数据不得
手改或提交到公开仓库。

## 保留与停止扩展的边界

| 类别 | 决策 | 下一步验收 |
|---|---|---|
| PDF/Markdown 解析、抽取、来源和时间索引、查询 | 保留并维护；优先修准确性和成本问题 | 抽取正确性、来源可定位、检索覆盖、费用可测 |
| PIT、隐私、schema、冻结来源、shadow/生产隔离 | 保留；不是可随意删除的冗余 | 原有约束测试持续通过 |
| profiles、weighted context、recipes、tool gaps | 暂停新增规则与扩展；维护已接入消费者 | 先列出每个被读取字段，再对排序/附加内容做独立消融 |
| 自动 recipe 扩张、工具提案、额外治理汇总 | 暂停新增产物；保留仍被现有验收依赖的部分 | 无消费者且无必要边界职责的链，才可连同 CLI/schema/tests 一起删除 |
| RKE 使用率与衍生 Agent 评分 | 不再使用事后检索补证据 | 先建立真实运行归因，才讨论评分权重 |

删除顺序：先移除错误归因和确定无消费者的辅助代码；再迁移上下文消费者以减少十类
输入的耦合；最后删除迁移后失去消费者的派生链。每一步独立审阅，不扩展通用框架。
暂停扩展不暂停现有隐私、PIT 和生产门禁的维护。

## 三组价值实验协议

先回答“研报有没有帮助”，再回答“结构化处理值不值得”：

| 组 | 输入 | 比较问题 |
|---|---|---|
| A | 当前数据与基础工具，无研报内容 | 建立无研报基线 |
| B | 同一合格研报集合的原文片段检索，保留来源和可得时间 | B−A：获取研报本身的价值 |
| C | 同一合格研报集合的 RKE 结构化抽取检索，保留来源和可得时间 | C−B：抽取及结构化处理的增量价值 |

第一次 C 只检验最小结构化核心；复杂性能加权、recipe 建议等应在后续独立消融中
评估。当前完整 RKE 上下文不是这个最小 C，不能直接改名替代。

1. 在看结果前冻结 episode/date、模型及解码参数、prompt 版本、当前数据、合格来源
   集合和判分规则。同一 episode 做配对比较，三组使用隔离状态，避免缓存、消息历史、
   仓位或先前组输出泄漏。只允许预先声明的研报输入差异。
2. B/C 使用相同检索任务、来源可得时间、文档候选范围、上下文 token 上限和截断规则。
   不以相同 item 数冒充相同预算；记录实际 token、检索/抽取耗时、LLM 成本和缓存命中。
   抽取成本分别报告首次建设与重复查询的摊销，A 不靠填充无意义文本消耗预算。
3. 报告发表时间不等于系统可得时间。当前数据、修订值、训练排序用的 outcome labels
   均须满足 as-of；未来价格只用于事后评分。LLM 不担任正确性标签来源。
4. 先选少量覆盖不同市场状态的 episode 检查分组隔离、来源绑定和实际消费是否成立；
   这些是流程检查。之后按预登记的最小有用增益、波动估计和预算确定评估样本量，
   保留未用于调参的样本，不能把一次 smoke 当成价值结论。
5. 主指标为对固定事实题的错误率、无法支持的断言比例及来源可核验率；用盲评或
   预先冻结的非 LLM 标签。带方向/期限的预测单列命中或校准指标，决策稳定性用重复
   运行的分歧衡量，不把“更稳定”自动当作“更正确”。交易回报仅做 shadow 次级指标，
   并遵守 T+1、成本和独立样本约束。
6. 报告每个 episode 的配对差值、总体区间和全部失败/缺失样本；不把相关 Agent 或
   同一报告的重复窗口当作独立样本扩大 N。预先定义可接受成本和最小有用增益。
   C−B 未达到该标准且成本更高时，优先保留 B 的简单检索；证据不足时继续保持收缩
   状态，不宣称结构化一定无效。B−A 也无可用增益时，重新评估 Agent 是否需要研报。

## 执行前缺口

目前没有三组实验的完整执行 runbook，也没有 A/B/最小 C 的隔离入口及可直接消费的
逐 Agent 归因记录。本文件不给出虚构命令，也不创建新 driver、harness 或旁路。
实施实验入口前需要明确这些合同变化，并按仓库规则取得所需的执行路径授权。

A 不能通过关闭必要证据检查或伪造“无数据”回执实现；B 的原文及日志必须留在合法
授权的私有边界，不能塞进 public-safe context；C 的候选和排序规则必须预先冻结。
runbook 还需绑定具体的私有输入快照、prompt、模型配置、样本量和成本预算。
这些条件完成前，只能报告管线检查与实现状态，不能报告三组收益或生产效果。
